## Objective

Make both `/deep-review`'s and `/review-plan`'s default rendered reports less verbose without losing any data: Critical and Important findings keep full detail (Severity/Category/Location/Evidence/Suggestion); Minor findings render as a single compact line (Severity/Category/Location/one-line summary only). A new `--verbose` flag (on both skills) restores today's full-detail rendering for every severity including Minor. Every report — compact or verbose, on either skill — ends with an explicit pointer to a persisted per-harness JSON state file, so the user can `jq`/grep the full underlying data instead of asking for a re-summary. `/review-plan` does not currently persist a per-run findings file the way `/deep-review` does (`.deep-review/latest-*.json`); this plan adds a comparable `.review-plan/latest-*.json` file (per-harness) as net-new functionality, so both skills end up with a symmetric footer rather than one skill pointing at a file and the other explaining why it can't. **The two files are symmetric in footer position and write-timing — not in top-level schema, and not fully in write-failure *enforcement* (corrected, fixed post-third `/review-plan` pass, 2026-07-14: both skills share the same intended write-failure reaction — warn and force full-verbose — but only review-plan's is script-enforced via `persist-review-state.sh`'s exit code; deep-review's remains unenforceable prose with no failure-detection surface, see Requirement 3).** Deep-review's actual persisted file is a `schema_version: 1` run-state wrapper (`run_id`/`base_commit`/`head_commit`/`diff_hash`/`review_focus_hash`/per-lens raw findings, needed for `--continue` resumability, which review-plan has no equivalent of); review-plan's persisted file is the `schema_version: 2` reconciled envelope itself (`summary`/merged `findings`/`related`, per Requirement 8's grilled decision), since review-plan's footer promises to let the user `jq` exactly what the rendered report was based on. Only the per-finding objects nested inside each wrapper share an identical shape (the GENERIC block's `{lens, severity, category, file, line, summary, evidence, suggestion}`, confirmed byte-parity-checked across all 4 targets) — the wrappers around them do not match and should not be assumed to.

## Requirements

### `/deep-review` (Phases 1-4)

1. **Step 5 default rendering change** (both mirrors): Critical and Important findings render exactly as today (full `Lenses`/`Evidence`/`Suggestion` sub-bullets). Minor findings render as a single line: `- **[Category]**: [one-line summary] (file:line)` (parenthesized location after the summary, matching `scripts/render-reconciled-report.sh`'s existing summary-first title-line convention `- **[category]**: [summary] at [file:line]`, but using a compact `(...)` separator instead of "at" for the single-line form) — no `Evidence:`/`Suggestion:` sub-bullets, no `Lenses:` sub-bullet expansion beyond what fits inline. When a Minor finding is unanchored (both `file` empty and `line` absent, per the GENERIC block's "Unanchored findings" case), the compact line omits the location segment entirely — `- **[Category]**: [one-line summary]` — with no trailing `(file:line)` and no "see also" suffix, since unanchored findings never participate in the Related-findings mechanism. The underlying data still carries all five fields (Severity, Category, Location, Evidence, Suggestion); only the *rendered* Minor tier omits Evidence/Suggestion prose from display. This same compact/`--verbose` rule applies to the continuation template's "New findings" `#### Minor` subsection, not just the main Step 5 template — it is not optional or "confirm if applicable," it is a firm requirement (see Phase 1). The compact Minor line therefore keeps `[AUTO-FIXABLE]` on the title line when the finding's `auto_fix_status` is `would_apply`; compact mode never strips it.

## Open Questions (for human decision before/at review-plan time)

1. **`scripts/render-reconciled-report.sh` scope** (this is the former Open Question 2 — renumbered to 1 now that the rubric-ownership question is settled, see below): this script is confirmed (via Explore) to be a *shared* reference renderer — its header comment states it encodes the report template for **both** `deep-review` and `review-plan`, it is invoked only by tests (`tests/reconciliation/test-renderer.sh`, `test-renderer-v1-rejects-v2.sh`), and it is deliberately **not bundled** into either installed skill (`scripts/lib/bundle-map.sh`) — the running review always renders "by hand" from the SKILL.md prose template, never by invoking this script live. This is now shared infrastructure for **both** in-scope skills (deep-review and review-plan), not deep-review alone — the resolution below applies uniformly to both. Two options:
   - **(a) Leave the script rendering full Evidence/Suggestion for all severities, unchanged.** Neither `deep-review`'s nor `review-plan`'s new compact-Minor rendering gets golden-file coverage from this script; the script's own doc comment ("all fields... MUST be preserved") becomes slightly stale for both skills' new default behavior (though still accurate as a description of the *underlying data*, and still accurate for whichever skill's rendering the tests still exercise against full-detail mode). Cheapest, no shared-script risk, but leaves both new compact-rendering paths without automated regression coverage beyond a manual walkthrough.
   - **(b) Add a `--compact-minor` (or `--verbose`) flag to the script itself**, mirroring the SKILL.md flag on both skills, so both skills' compact and verbose paths get golden-file coverage. Higher fidelity, but changes a script two skills already share, doubling the fixture surface (deep-review compact/verbose + review-plan compact/verbose).
   **Resolved (grilled decision, 2026-07-12): option (b).** The user chose golden-file coverage over the plan's original recommended default — `scripts/render-reconciled-report.sh` gains a `--verbose` flag and both skills get new fixture pairs, accepting the doubled fixture surface and shared-script touch as worth it for automated regression coverage of the plan's primary behavior change. See Phase 8 and Findings for the resulting task list.
   **Flag polarity, fixed post-`/review-plan` (2026-07-13):** the script's **default** (no flag) is compact-Minor, matching both skills' own default; passing `--verbose` restores full-detail rendering for every severity, reusing the exact flag name both skills already use rather than inventing a `--compact-minor` on-switch. This removes an internal contradiction the original draft had (one clause said compact-Minor was already the default while an adjacent sentence said "pass `--compact-minor` to exercise the default path" — the two could not both be true). Because the default flips, five pre-existing `tests/reconciliation/expected/*.rendered.md` goldens whose Minor sections currently assert full detail (`auto-fix-v2-docstring-typo`, `auto-fix-v2-pass-through`, `auto-fix-v2-reject-statuses`, `same-category-different-line`, `auto-fix-v2-empty-fields`) would otherwise silently start failing under the new default. Phase 8 adds `--verbose` to those five fixtures' invocations in `tests/reconciliation/test-renderer.sh` (their point is unrelated to severity-tier rendering — auto-fix status handling, category cross-references — so preserving their original full-detail assertions via the flag is safer than regenerating their golden content to compact form, which could silently narrow what they actually check).
