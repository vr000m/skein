## Objective

Make both `/deep-review`'s and `/review-plan`'s default rendered reports less verbose without losing any data: Critical and Important findings keep full detail (Severity/Category/Location/Evidence/Suggestion); Minor findings render as a single compact line (Severity/Category/Location/one-line summary only). A new `--verbose` flag (on both skills) restores today's full-detail rendering for every severity including Minor. Every report — compact or verbose, on either skill — ends with an explicit pointer to a persisted per-harness JSON state file, so the user can `jq`/grep the full underlying data instead of asking for a re-summary. `/review-plan` does not currently persist a per-run findings file the way `/deep-review` does (`.deep-review/latest-*.json`); this plan adds a comparable `.review-plan/latest-*.json` file (per-harness) as net-new functionality, so both skills end up with a symmetric footer rather than one skill pointing at a file and the other explaining why it can't. **The two files are symmetric in footer position, write-timing, and write-failure behavior — not in top-level schema.** Deep-review's actual persisted file is a `schema_version: 1` run-state wrapper (`run_id`/`base_commit`/`head_commit`/`diff_hash`/`review_focus_hash`/per-lens raw findings, needed for `--continue` resumability, which review-plan has no equivalent of); review-plan's persisted file is the `schema_version: 2` reconciled envelope itself (`summary`/merged `findings`/`related`, per Requirement 8's grilled decision), since review-plan's footer promises to let the user `jq` exactly what the rendered report was based on. Only the per-finding objects nested inside each wrapper share an identical shape (the GENERIC block's `{lens, severity, category, file, line, summary, evidence, suggestion}`, confirmed byte-parity-checked across all 4 targets) — the wrappers around them do not match and should not be assumed to.

## Requirements

### `/deep-review` (Phases 1-4)

1. **Step 5 default rendering change** (both mirrors): Critical and Important findings render exactly as today (full `Lenses`/`Evidence`/`Suggestion` sub-bullets). Minor findings render as a single line: `- **[Category]**: [one-line summary] (file:line)` (parenthesized location after the summary, matching `scripts/render-reconciled-report.sh`'s existing summary-first title-line convention `- **[category]**: [summary] at [file:line]`, but using a compact `(...)` separator instead of "at" for the single-line form) — no `Evidence:`/`Suggestion:` sub-bullets, no `Lenses:` sub-bullet expansion beyond what fits inline. When a Minor finding has a "Related findings" cross-reference (same `(file, line)`, different category, per the GENERIC block), the compact line appends a terse inline suffix instead of the full sub-bullet: `- **[Category]**: [summary] (file:line) — see also [Other Category] at same location`. When a Minor finding is unanchored (both `file` empty and `line` absent, per the GENERIC block's "Unanchored findings" case), the compact line omits the location segment entirely — `- **[Category]**: [one-line summary]` — with no trailing `(file:line)` and no "see also" suffix, since unanchored findings never participate in the Related-findings mechanism. The underlying data still carries all five fields (Severity, Category, Location, Evidence, Suggestion); only the *rendered* Minor tier omits Evidence/Suggestion prose from display. This same compact/`--verbose` rule applies to the continuation template's "New findings" `#### Minor` subsection, not just the main Step 5 template — it is not optional or "confirm if applicable," it is a firm requirement (see Phase 1). The continuation template's "Prior findings" list (already one-line per finding) is unaffected.
2. **`--verbose` flag** (both mirrors): added to `argument-hint` and to Input Resolution / "What This Skill Reviews" as a modifier flag (composable with `--full`, `--pr`, `--continue`, `--auto-fix=trivial` — it changes only rendering, not scope resolution or lens dispatch). **Flag grammar (grilled decision, 2026-07-12): flags may appear in any order; `--verbose` is a pure rendering switch and has no conflict case with any other flag, since it never touches scope resolution or dispatch.** When passed, every finding at every severity renders with full Evidence/Suggestion detail — i.e., today's current behavior, unconditionally. This includes the continuation template's "New findings" `#### Minor` subsection (Requirement 1) — `--verbose` restores full detail there too, not only in the main Step 5 template.
3. **JSON pointer footer** (both mirrors, both compact and verbose modes): every rendered report — Step 5's normal template and the continuation-mode template — ends with an explicit line naming the per-harness state file path (`.deep-review/latest-claude.json` on Claude, `.deep-review/latest-codex.json` on Codex) so the user can inspect the full per-lens findings directly (e.g. `jq '.lenses' .deep-review/latest-claude.json`) instead of asking for a re-summary. The footer line appears immediately **before** the `**Next steps**:` line — this is a fixed position, not a per-mirror choice. **This footer position is verified by manual walkthrough only, never by golden fixture (fixed post-`/review-plan`, 2026-07-13):** `scripts/render-reconciled-report.sh`'s own header states header/trailer lines (including `**Next steps**:` and any footer before it) are "skill-specific and NOT emitted here" — it emits only the markdown body fragment. Do not imply Phase 8's new fixtures cover the footer; they cover the compact-Minor body only. **Write-failure contract (grilled decision, 2026-07-12; corrected 2026-07-13 — this is net-new for deep-review, not a pre-existing behavior, see below):** best-effort write; if the state-file write fails, print a one-line warning in the report ("Could not persist findings JSON: <reason>") and render that run in full-verbose mode regardless of `--verbose`'s actual value — no atomic-write/temp-file/rename mechanics.
4. **Four-file symmetry**: `plugins/skein/skills/deep-review/SKILL.md`, `plugins/skein/skills/deep-review/rubric.md`, `plugins/skein-codex/skills/deep-review/SKILL.md`, `plugins/skein-codex/skills/deep-review/rubric.md` all move together. `rubric.md` must stay byte-identical between the two mirrors (enforced by `scripts/check-prompt-parity.sh`'s rubric-diff loop, lines 60-92).
5. **Reconcile rubric wording**: `rubric.md`'s "Finding Quality" section currently states "Each finding has all five fields: Severity, Category, Location, Evidence, Suggestion" (line 14). This must be reworded so it is still true of the *underlying reconciled data* (all five fields always exist) while being explicit that the *default rendered report*'s Minor tier intentionally omits Evidence/Suggestion from display — the rubric and the SKILL.md report template must not contradict each other. Because `rubric.md` "doubles as a Managed Agents outcome rubric (text mode)" (`rubric.md:3`) and a text-mode grader sees only the *rendered report*, never the underlying JSON, the new gradeable criterion must be stated in terms of what is observable in the rendered output, not just "the data has five fields": e.g. "Critical/Important findings render all five fields (Severity/Category/Location/Evidence/Suggestion); Minor findings render Category+Location+one-line summary by default (Evidence/Suggestion intentionally omitted from the default rendering, restored with `--verbose`)." See Technical Specifications for exact proposed wording.

## Open Questions (for human decision before/at review-plan time)

1. **`scripts/render-reconciled-report.sh` scope** (this is the former Open Question 2 — renumbered to 1 now that the rubric-ownership question is settled, see below): this script is confirmed (via Explore) to be a *shared* reference renderer — its header comment states it encodes the report template for **both** `deep-review` and `review-plan`, it is invoked only by tests (`tests/reconciliation/test-renderer.sh`, `test-renderer-v1-rejects-v2.sh`), and it is deliberately **not bundled** into either installed skill (`scripts/lib/bundle-map.sh`) — the running review always renders "by hand" from the SKILL.md prose template, never by invoking this script live. This is now shared infrastructure for **both** in-scope skills (deep-review and review-plan), not deep-review alone — the resolution below applies uniformly to both. Two options:
   - **(a) Leave the script rendering full Evidence/Suggestion for all severities, unchanged.** Neither `deep-review`'s nor `review-plan`'s new compact-Minor rendering gets golden-file coverage from this script; the script's own doc comment ("all fields... MUST be preserved") becomes slightly stale for both skills' new default behavior (though still accurate as a description of the *underlying data*, and still accurate for whichever skill's rendering the tests still exercise against full-detail mode). Cheapest, no shared-script risk, but leaves both new compact-rendering paths without automated regression coverage beyond a manual walkthrough.
   - **(b) Add a `--compact-minor` (or `--verbose`) flag to the script itself**, mirroring the SKILL.md flag on both skills, so both skills' compact and verbose paths get golden-file coverage. Higher fidelity, but changes a script two skills already share, doubling the fixture surface (deep-review compact/verbose + review-plan compact/verbose).
   **Resolved (grilled decision, 2026-07-12): option (b).** The user chose golden-file coverage over the plan's original recommended default — `scripts/render-reconciled-report.sh` gains a `--verbose` flag and both skills get new fixture pairs, accepting the doubled fixture surface and shared-script touch as worth it for automated regression coverage of the plan's primary behavior change. See Phase 8 and Findings for the resulting task list.
   **Flag polarity, fixed post-`/review-plan` (2026-07-13):** the script's **default** (no flag) is compact-Minor, matching both skills' own default; passing `--verbose` restores full-detail rendering for every severity, reusing the exact flag name both skills already use rather than inventing a `--compact-minor` on-switch. This removes an internal contradiction the original draft had (one clause said compact-Minor was already the default while an adjacent sentence said "pass `--compact-minor` to exercise the default path" — the two could not both be true). Because the default flips, five pre-existing `tests/reconciliation/expected/*.rendered.md` goldens whose Minor sections currently assert full detail (`auto-fix-v2-docstring-typo`, `auto-fix-v2-pass-through`, `auto-fix-v2-reject-statuses`, `same-category-different-line`, `auto-fix-v2-empty-fields`) would otherwise silently start failing under the new default. Phase 8 adds `--verbose` to those five fixtures' invocations in `tests/reconciliation/test-renderer.sh` (their point is unrelated to severity-tier rendering — auto-fix status handling, category cross-references — so preserving their original full-detail assertions via the flag is safer than regenerating their golden content to compact form, which could silently narrow what they actually check).
