It is deleted on every path (consume-once), so a call with no fresh file fails closed with `missing slug file` instead of reusing an earlier run's slug, and `cmd_cleanup` now removes `<repo-root>/.fanout/` alongside the state file. `cmd_cleanup` no longer trusts the state file for its targets at all: it reads `git worktree list --porcelain` once and acts only on entries whose path is a sibling of the repo root named `<repo-name>-fanout-*` AND whose branch is under `refs/heads/fanout/`, deleting the branch git itself attached to each (always after a `--`). A hand-deleted worktree is still listed by git (marked `prunable`) with its branch line, so the old state-file branch fallback and its regex are gone; `agents[]` is now read for a diagnostic only, and a worktree it names that git does not attribute to fan-out is reported and left alone. `cmd_setup` normalises its repo-root argument once (refusing a relative or `..`-bearing one) so the worktree path it builds is the path its own guards judged — a root spelled `<repo>/.` used to nest the worktree inside the checkout, where cleanup then refused to remove it. The `.fanout/` directory is created by the skill's one-time Phase 3 preamble, and Phase 5 now re-derives worktree and branch names from that same porcelain listing rather than spelling state-file values into shell commands. Covered by `tests/plugin/test-fanout-slug-guard.sh` (32 assertions, including that an accepted slug is used verbatim for the branch and worktree), run by `just plugin-tests`; `fan-out.sh` itself joins `just lint-scripts` under `shellcheck` only, pending a tab reformat.

## [0.6.0] - 2026-08-24

### Added
- **Bounded Codex gate + size-scaled budgets (`skein:review-gauntlet`, both mirrors).** `gate_run_bounded` (new harness-neutral `lib/gate-bounded.sh`, added to `GAUNTLET_LIB_PARITY_FILES`) runs the Codex CLI under a process-group-scoped timeout — GNU `timeout` when present, else a `python3 os.setsid`+exec shim — and writes an envelope on **every** exit path: success wraps the tool output with `duration_s`; invalid/truncated JSON tool-out becomes `status: "error"`; expiry writes `status: "skipped"` with a `DEGRADED:`-prefixed note and no tool-out (`gate_run_bounded` itself always returns 0 once the envelope is written; the `skipped` status is what later drives `run-gate.sh normalize`'s own `exit 4`). `run-gate.sh normalize` reads only the envelope path, closing a half-written-output hole. Budgets come from a new canonical `scripts/lens-budget.sh` (`BUNDLE_SHARED`, promoted from a review-gauntlet-only `bundle_extra_for` entry once deep-review/review-plan also began invoking it for their own per-lens budgets), sized by kind (`lens`/`plan-lens`/`codex`) with floors (5m/5m/20m) and caps (30m/30m/45m); a budget-killed gate is always reported DEGRADED, never silently clean. Expiry is measurement-backed (`exit != 0 AND (exit == 124 OR duration >= budget)`), and the belt-and-braces sweep is pgid-scoped (sidecar pgid file, `pgrep -g`, guarded against pgid 0/1/self) rather than a host-wide `pkill -f` pattern kill.
- **Disk-first streamed lens results (`skein:deep-review`, `skein:review-plan`, both mirrors).** New canonical `scripts/persist-lens-result.sh` (lens-side writer) and `scripts/collect-lens-results.sh` (orchestrator-side reader), plus `scripts/lib/persist-common.sh`'s shared append-line helper, all bundled via `bundle_extra_for` into deep-review's and review-plan's mirrors only — never review-gauntlet's, which spawns no lens subagents of its own. Each lens subagent streams typed lines (`start`/`progress`/`finding`/`done`) to its own `<state-dir>/lenses/<run-id>/<lens>.<attempt>.jsonl` — one writer per file, no locking needed. The collector is the sole reader: it merges attempts, cross-attempt-dedups findings by `(file, line, category)`, and reports a `completed|partial|timed_out|errored|skipped` status per lens (absent = `missing`). A parseable Agent return with no `done` line on disk is written by the orchestrator itself (attempt 1, no respawn). One respawn only, for `partial`/`missing` lenses, against the orchestrator-owned assigned-units list. That list travels as a **units file** — `--expected-file <path>`, one JSON object mapping lens name to unit array, written by the orchestrator with its file-write tool and read back with jq — never as the `--expected` argv flag, whose value the orchestrator's own shell substitutes before the collector is entered, so quoting a diff-derived path into it does not help. The file lives in the run's own lens state directory, `<state-dir>/lenses/<run-id>/expected.json` (i.e. `.deep-review/lenses/<run-id>/expected.json`, `.review-plan/lenses/<run-id>/expected.json`), alongside the attempt files and already gitignored, and it is written once: the respawn narrows the retry prompt's unit list, never the file, since the collector derives `assigned`/`reviewed`/`unreviewed` from it. A unit is carried as a JSON string end-to-end, so a comma, a newline or any other byte in a path or plan heading survives verbatim; the comma restriction applies only to the `--expected`/`--units` CSV spellings, where the comma genuinely is the separator. `persist-deep-review-state.sh` gains `--from-collector` (collector stdout piped to persist stdin) so deep-review's `.lenses` summary and its `--continue` consumer derive from the same collect→persist path; `persist-review-state.sh` is untouched (review-plan has no `--continue` consumer and reads collector output directly). Budget-wake is a `Bash(run_in_background)` sleep timer, not Monitor — verified live in a Phase 2 spike. Codex sequential mode runs the same collector; only the respawn step is skipped (no concurrent spawn there).
- **Regression-loop stop + gate-status rows (`skein:review-gauntlet`, both mirrors).** `convergence-ledger.sh` gains ledger-owned `claimed → fixed` promotion: `--claimed-keys` (a newline-separated regression-key file, replacing `--fixed-keys`) — the fixer subagent returns claimed finding OBJECTS (`{claimed:[...]}`), and the orchestrator derives the keys from them via the new `scripts/finding-key.sh` before writing the file; a claim is promoted only by the *next* complete full pass (`pass_type == full ∧ unresolved == 0 ∧ present_supplied`), never same-round, never on a degraded gate, never when `--present-keys` is absent — three independently-blocked vacuous-promotion paths. A new `regression` decision fires when a previously-promoted `fixed` key reappears in `--present-keys` on a later full or confirm pass (terminal; `--last-decision` reads persisted state and never re-promotes). Regression keys (`finding-key.sh`: a length-prefixed `sha1(file, category-lowercased, summary-lowercased+whitespace-collapsed)` — `file` kept verbatim, never lowercased, so two distinct paths differing only in case never collide) are deliberately distinct from the reconciler's line-anchored dedup key, so a shifted-line reappearance still matches. `run-gate.sh status-row` adds a `gate, status, duration_s, findings, degraded_reason` row per gate for the gauntlet's round loop.
- **`.claude/CLAUDE.md` hygiene sections + ruff `# noqa` fix (meta).** Repo `.claude/CLAUDE.md` gains `## Testing`, `## Facts vs Inference`, and `## Security & Diff Reviews` sections (upstreamed to the live `~/.claude/CLAUDE.md` via the sync-computer repo, which owns that global file — not edited here). New `tests/plugin/noqa-probe.sh` reproduces the incident mechanism directly against `~/.claude/hooks/format-on-edit.sh` (defaults `HOOK_PATH` to that live path when unset, so the bare Validation cmd is non-vacuous): RUF100-selected `ruff check --fix` was confirmed to strip an unused `# noqa` (`STRIPPED`, exit 1) before the fix, and confirmed to leave it intact (`SURVIVED`, exit 0) after adding `--ignore RUF100` to the hook's ruff invocation. The probe's scratch project selects RUF100 itself to guarantee reproduction — the original incident's actual project ruff config was never identified, so this confirms the mechanism, not the specific trigger. New `tests/plugin/test-claude-md-hygiene.sh` asserts the three sections' presence/content: 4/4 by default (the global-file check SKIPs unless `GLOBAL_CLAUDE_MD` is set), 7/7 with `GLOBAL_CLAUDE_MD` pointed at the live file; it also asserts the hook's `ruff check --fix` line carries `--ignore RUF100`.

## [0.5.2] - 2026-07-16

### Added
- **`skein:release` (both Claude and Codex).** A new skill that is user-invoked-only on Claude; Codex remains model-invocable and requires explicit confirmation before any mutation. It derives a GitHub release's title and body from a `CHANGELOG.md` `## [X.Y.Z] - date` section (Keep a Changelog format) and creates or re-syncs the git tag and GitHub release to match, in one canonical shape: title `<repo> vX.Y.Z — <highlight>`, body = an optional `## What's New` summary paragraph + the section content with its header stripped + a trailing `**Full diff:**` compare link. `/release audit` scans every tag/CHANGELOG version repo-wide for missing tags, missing releases, or drifted title/body and reports a fix-opt-in punch list. Replaces skein's own ad hoc, hand-typed `gh release create`/`edit` calls, which had drifted into three visibly different release-note shapes across its first 11 releases (all retrofitted to the canonical shape in the same session). Before creating a brand-new tag, the skill requires a clean worktree and pins the exact confirmed commit SHA; re-syncing an existing tag (local-only or already on origin) instead shows the target commit for human judgment, without a worktree requirement. A TOCTOU re-verify immediately precedes every tag/release mutation, comparing the tag's live origin commit against what was confirmed. See `docs/dev_plans/20260712-feature-release-skill.md`.

## [0.5.0] - 2026-07-11

### Added
- **`skein:grill` (both Claude and Codex).** A new standalone, user-invocable skill that runs a relentless, one-question-at-a-time interview over any plan file or freeform idea. Every candidate topic is first classified as a **fact** (verifiable from the codebase — looked up, never asked) or a **decision** (a genuine judgment call, no single correct answer); each decision gets exactly one recommended resolution and blocks until the user accepts, proposes an alternative, or waives it — no batching, no undifferentiated option lists. The skill document splits into two independently-anchored sections: § Interview Mechanics (the reusable fact/decision protocol, referenced inline by other skills) and § Target Acquisition & Persistence (standalone-only: plan-file-vs-freeform target parsing, review-marker refusal check, and `/dev-plan update`-or-conversational-summary persistence).
- **`/review-plan` Step 6.4 delegates grill-eligible findings to `skein:grill`.** Findings are classified grill-eligible by `category` (architecture/component-boundary, third-party integration, security, rate-limiting) — never by lens — with `Nonexistent Reference` findings explicitly excluded and a fixed topic-priority tiebreak (architecture/component-boundary > third-party integration > security > rate-limiting) for candidates spanning two eligible topics. Grill-eligible findings are presented one at a time via `grill/SKILL.md` § Interview Mechanics referenced inline, in-session (no skill activation or subagent spawn); resolved decisions are written above the plan's review marker via `/dev-plan update` prefixed `Decision (grilled):`, waived findings still route to `### Review Waivers`. Standard (non-grill-eligible) findings keep today's unmodified 2-3-option Clarify behavior; `--batch` still skips Step 6.4 entirely, including grill classification. `rubric.md` (both mirrors) gains a new "Grill Discipline" section documenting the classification rule and tiebreak, byte-identical across `.claude`/`.codex` per `scripts/check-prompt-parity.sh`. `grill` is added to the managed-skill inventory in `scripts/check-prompt-parity.sh` and `tests/parity/test_skill_md_presence.py`.

## [0.4.1] - 2026-07-11

### Added

Guardrail 4 requires the conductor to verify the fixer's per-round claims against live repo state (`git status --short` / `git diff --stat`) before folding the round into the convergence-ledger call or the operator-facing report, rather than trusting the fixer subagent's self-report text — mirroring the existing verify-don't-trust discipline already applied to gate output. ### Fixed
- `apply-auto-fix-code.sh`'s before/after type guard now rejects any non-string `after` (including `null`), matching `audit-auto-fix-eligibility.sh` exactly. It previously treated a JSON `null` `after` as an accepted "delete the matched line(s)" signal, which — combined with `jq -r`'s rendering of `null` as the literal text `"null"` — could write that string into the source instead of deleting the line. Legitimate deletions are already expressed as an empty string, not `null`, so tightening the guard closes the divergence without affecting real deletions. Propagated to all four bundled copies (skein/skein-codex × review-gauntlet/deep-review).

The warning partitions on the same separator the map itself uses (a BEL control character, not `|`), so a literal `|` in a file/category value can't make the warning's grouping diverge from what the map actually collapses.

New `tests/gauntlet/test-codex-capability-gap-unresolved.sh`.

Mirrored into the Codex tree. New regression case (`9c`) in `test-convergence-ledger.sh`.

## [0.2.2] - 2026-06-12

### Fixed
- Quoted SKILL.md frontmatter values that contain multiple bracketed argument tokens or colon-bearing prose so Codex can load all bundled `skein:*` skills without YAML parse warnings.
- `/conduct` review-marker hashing (`conduct/marker.py`) is now byte-faithful, matching the documented recipe (`git hash-object` of the bytes above the marker line). `strip_marker_for_hashing` previously popped the blank line that normally precedes the marker and round-tripped through `splitlines()`/`join()`, silently normalizing CRLF→LF; `compute_plan_hash` also read via `read_text`, translating line endings before hashing. Together these made the computed hash disagree with `git hash-object` of the above-marker bytes whenever a plan had a blank line before its marker (the common markdown style) or used CRLF endings — so preflight false-flagged a valid plan as stale (hard-stopping a first run, or, on `--resume`, rewriting the marker into a form no byte-faithful external checker accepts). Hashing now slices the plan at the marker line's exact byte offset with line endings preserved. **Migration:** markers written by `/review-plan` with a blank line before them now validate correctly; any marker previously written by the old `marker.py` blank-popping path on such a plan reports stale once and refreshes on the next `/review-plan` or `--resume`.

- `write_marker` now hashes the exact bytes it writes above the marker. It previously hashed the contract *before* appending the trailing newline that separates the contract from the marker line, so marking a plan that had no trailing newline (e.g. a freshly authored plan) recorded a hash of bytes that were never written above the marker — leaving the plan stale the instant `/review-plan` marked it, and `/conduct` would then reject a plan the user had just reviewed. (Pre-existing; surfaced by adversarial review.)
- `write_marker` reads and writes plan bytes directly (`read_bytes`/`write_bytes`) instead of text-mode `read_text`/`write_text`. Text mode applies universal-newline translation whose direction is platform-dependent — on Windows `write_text` re-expands `\n` to `\r\n` on disk — so the bytes `write_marker` hashed could differ from the bytes `compute_plan_hash` (byte-faithful since this release) reads back, marking a CRLF plan stale on Windows the instant it was written. Reading and writing raw bytes keeps both sides on identical bytes on every platform and preserves a plan's existing line endings.

### Changed
- Hardened the review-marker locators: `last_marker_index` (line index) and `_marker_line_span` (byte offset) now share one `_scan_marker_lines` fence-tracking core so they can never drift to different markers on the same plan. Documented the byte-faithful invariant in `conduct` and `review-plan` SKILL.md (both mirrors) to prevent re-introducing line-ending/blank-line normalization. Added `tests/parity/test-conduct-marker-parity.sh` (wired into `just parity-tests`) asserting `conduct/marker.py` stays byte-identical across the skein and skein-codex mirrors.
