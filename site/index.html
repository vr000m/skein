Skills that check each other's work.

Skein is a set of Claude Code and Codex skills that chain planning, building and review into one loop. Each stage hands a checked artifact to the next, and nothing reviews its own output.

How the skills connect

A feature moves left to right. Pick a skill to see what it takes in, what it hands on, and the command to run it.

Why that makes the code sturdier

None of the skills is clever on its own. The robustness comes from how they are wired together.

Mistakes are caught where they are cheapest

grill and review-plan check a plan against the real codebase before any code exists. A wrong assumption costs one edit to a markdown file, not a rewrite.

Nothing marks its own homework

Every review lens, build phase and fixer starts in a fresh context. They cannot inherit the author's blind spots, and the main session stays free to coordinate.

Loops end on evidence

review-gauntlet goes round again until findings stop appearing. State lives on disk in .conduct/ and .gauntlet/, so an interrupted run resumes with --resume instead of starting over.

Also in the box

Standalone skills you can call at any point. Where one pairs with part of the pipeline, it says so.
